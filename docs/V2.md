# Turbo Karts Arena 2.0 — dossier de revue

Branche de développement : `codex/arena-v2`, basée sur `main` après fusion de la PR PWA nº 2.
La version du package et de l'application est 2.0.0, avec versionCode Android 2.
Aucune fusion ni publication du site ou d'une release n'est effectuée par cette livraison.

## Contenu jouable

- Huit circuits : Côte Solaire, Canyon Écarlate et Néon Nuit sont conservés avec leur
  largeur +25 %. Autoroute des Alpes, Tokyo Express, Sahara Rally, Forêt Tropicale
  et Côte Méditerranéenne ajoutent cinq tracés indépendants et des niveaux de difficulté
  affichés. Chaque tracé utilise la même simulation, les collisions, le classement,
  les chronos, les tours et l'arrivée.
- Huit véhicules indépendants du pilote : Apex R4, Vector Formula, Nomad RX et Pulse
  Sprint (karts), Aerion S et Spectre RR (sportives), Terra X (motocross), Horizon GT
  (touring). Aucun nom, logo ou modèle de constructeur commercial.
- Modèles originaux créés en géométrie procédurale : carénages continus par sections,
  châssis, fourches, bras oscillants, amortisseurs, ailettes moteur, disques de frein,
  étriers, jantes et rayons, pneus, échappements, sièges, rétroviseurs, feux, bulles et
  valises du touring. Les pièces statiques sont regroupées par matériau ; roues et
  direction gardent leurs pivots. Un LOD conserve la silhouette à distance.
- Douze pilotes : les huit existants plus Lina Sol, Idris Sirocco, Aya Mori et Nilo
  Costa. Combinaisons, casques, bandes et visières différenciés. Posture assise des
  karts et jambes repliées/bras vers les guidons des motos ; le modèle montré dans
  le garage est le même qu'en course.
- Les motos ont des profils d'accélération, freinage, adhérence et réponse de direction
  distincts, un roulis borné en virage et une stabilité propre à chaque châssis.
  Le modèle reste arcade : pas de simulation complète de pneus, d'embrayage ou de chute.
- Garage 3D dans les deux hôtes, choix indépendant pilote/véhicule/circuit et trois
  niveaux IA : Découverte, Arcade et Expert. Le nombre de tours sélectionné est
  réellement appliqué à la course (1/3/5).
- Panneaux de virage, enchaînement, pente, chaussée humide, rétrécissement, travaux,
  rochers, tunnel et viaduc. Ils proviennent de la courbure, de la pente, de la largeur,
  de la météo ou des segments explicitement construits. Le placement vérifie toutes
  les portions du ruban pour éviter les autres branches d'un lacet. Les avertissements
  du HUD sont déclenchés par la distance restante, pas par un générateur aléatoire.
- Glissières avec contacts physiques, marquage central, voûtes de tunnel et luminaires,
  viaducs, reliefs, dunes, falaises, végétation, pluie et adhérence humide. Tokyo dispose
  d'un trafic décoratif animé instancié sur une voie parallèle, derrière les glissières ;
  les segments qui chevaucheraient une route jouable sont exclus.
- Pause, reprise, redémarrage, clavier, commandes tactiles simultanées et PWA conservés.
  Le bouton de dérapage devient « Glisse / turbo » pour une moto. L'ancien bouton son
  sans audio implémenté est retiré de l'hôte web ; aucun nouveau bouton factice.

Les modèles sont détaillés et optimisés par code, sans assets externes ou photogrammétrie.
Le style reste celui d'un jeu arcade original ; il ne s'agit pas de véhicules scannés.

## Contrôles et reproduction

```sh
npm ci
npm run typecheck
npm test
npm run test:v2
npm run preview:build
npx playwright install --with-deps chromium
npm run test:browser
npm run test:browser:v2
npm run test:pwa
```

Sur le cloud, le Chromium système bloque `file://` : lancer `PORT=5174 npm run
preview:serve`, puis utiliser `BROWSER_TEST_URL=http://127.0.0.1:5174/index.html`
et `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium` pour `test:browser`.
Les deux autres suites navigateur lancent leur serveur HTTP de test. Le réglage
`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` est aussi accepté par celles-ci.

`test:v2` vérifie les comptes, les profils, les modèles pour les 96 combinaisons
pilote/véhicule, la physique moto, le grip humide, les glissières, les collisions
entre toutes les paires de véhicules, les panneaux, les niveaux IA et 64 courses
complètes (huit circuits × huit véhicules). `npm test` conserve les tests historiques
et simule également trois tours sur les huit circuits.

`test:browser:v2` actionne le vrai menu, parcourt les douze pilotes, rend les huit
véhicules sur les huit circuits, vérifie les commandes simultanées, la pause/reprise,
le redémarrage, les avertissements, l'affichage portrait et un budget de rendu basse
qualité de 220 appels/250 000 triangles par image au maximum dans ces scènes de départ.
Les captures et mesures sont écrites dans `.preview/v2-captures/` et
`.preview/v2-performance.json`, sans ajout au dépôt des fichiers temporaires.

Le hook de test avance les mêmes pas de simulation mais ne dessine que leur dernière
image par défaut. Il évite de saturer le GPU logiciel avec 150 rendus synchrones
lors d'une assertion sur le chrono. Le benchmark exige au contraire le rendu de
chaque image ; les assertions fonctionnelles existantes restent actives.

Les tests PWA couvrent le manifeste, les icônes, le scope de type GitHub Pages,
le démarrage à froid hors connexion, une course sans réseau, les mises à jour et
la préservation des caches tiers. Ils couvrent aussi les deux distributions générées.

## Android et livraison

Le workflow Android exécute les suites, le prebuild Expo et `assembleRelease`.
Il fonctionne sur la PR et sur la branche V2 ; son APK est un artefact de build.
La publication d'une release exige désormais un lancement manuel sur `main` avec
l'entrée `publish_release` activée (désactivée par défaut).

Pour compiler localement avec Java 17, SDK Android 34, build-tools 34.0.0 et
NDK 26.1.10909125 :

```sh
npx expo prebuild --platform android --no-install
cd android
./gradlew assembleRelease --no-daemon --max-workers=2
```

Dans le cloud, le prebuild a été effectué dans une copie générée `.preview/native-build/`
pour conserver le checkout sans arborescence native générée. Les sources sont copiées
depuis le checkout et les dépendances partagées par un lien vers `node_modules`.
Les outils téléchargés restent hors du dépôt, avec vérification des checksums officiels.
Les réglages de proxy et le magasin de certificats du cloud servent uniquement à cette
machine ; TLS n'est pas désactivé.

L'APK de revue est signé avec la clé debug standard du template, comme le workflow
existant. Ce n'est pas une signature de distribution Play Store.

## Recette sur téléphone avant fusion

1. Installer l'APK de revue ou, après accord du propriétaire pour un hébergement
   de test HTTPS, ouvrir **la branche V2** dans Chrome Android. Le site de production
   continue à servir `main` tant qu'aucune fusion/publication n'est autorisée.
2. Vérifier le garage 3D, les douze pilotes, les huit véhicules et les trois niveaux IA.
3. Lancer chacun des huit circuits, puis une course avec chacune des huit machines.
   Tester aussi une course de 1 et de 5 tours. Contrôler le chrono et l'arrivée.
4. Maintenir deux doigts (direction + glisse ou frein), relâcher indépendamment,
   vérifier pause/reprise, redémarrage et changement d'application.
5. Observer les panneaux avant les courbes, les tunnels, les zones humides et les
   travaux. Confirmer que les poteaux, glissières et décors n'obstruent pas la route.
6. Installer la PWA, la fermer avec tous les onglets du jeu, passer en mode avion
   et relancer. Vérifier menu, choix de véhicule/circuit et course hors connexion.
7. Mesurer FPS, chauffe, stabilité et consommation sur téléphone réel en qualité
   Basse puis Haute. Vérifier le gyroscope et les dimensions des commandes.

Les captures cloud utilisent SwiftShader sur CPU. Leurs temps par image ne mesurent
pas un GPU Android, et huit images de départ ne constituent pas un test d'endurance.
Aucun téléphone physique ni émulateur Android n'est déclaré testé. La recette matérielle,
l'acceptation visuelle et la revue des modifications restent nécessaires avant fusion.

## Résultats de cette session

- TypeScript : hôtes React Native et navigateur validés.
- `npm test` : 37 tests réussis, dont trois tours terminés par l'IA sur les huit circuits.
- `npm run test:v2` : 85 contrôles réussis, dont 64 combinaisons circuit/véhicule.
- Régression navigateur historique : réussite, aucune erreur navigateur.
- Régression V2 : huit véhicules/circuits, douze pilotes, tactile simultané,
  pause/reprise/redémarrage et portrait validés, aucune erreur navigateur.
- PWA : manifeste, démarrage à froid hors ligne, course hors ligne, mise à jour,
  conservation des caches tiers et distributions générées validés.
- Deux compilations web consécutives produisent des `index.html` et `service-worker.js`
  identiques. Le bundle web demeure autonome (environ 670 Ko de HTML non compressé).
- Mesure basse qualité sur les huit scènes de départ : 80–124 appels de rendu,
  140 046–156 056 triangles/image ; rendu logiciel cloud d’environ 216–315 ms/image
  lors de cette exécution. Il ne s'agit pas de FPS Android ni d'une mesure d'endurance.
- Prebuild Android réussi ; Java 17, SDK 34, build-tools, NDK et Gradle préparés.
  Le bundle JavaScript/Hermes Android a été compilé par Gradle. **APK non obtenu** :
  téléchargement de `react-android-0.74.5-release.aar` et `hermes-android-0.74.5-release.aar`
  bloqué en HTTP 403 après redirection de Maven Central vers `repo.reactnative.dev`.
  Le domaine requis est enregistré dans le brouillon des paramètres réseau cloud,
  avec les règles existantes conservées. L'enregistrement/publication de l'environnement
  cloud par le propriétaire doit l'activer ; cet ajout ne publie pas le jeu.
- API GitHub : consultation/création de PR refusée avec « Forbidden ». Le push Git
  demeure une opération distincte. La création manuelle de la PR depuis la branche
  est la solution si le droit API reste absent.

La validation finale n'est donc pas déclarée complète : il reste l'APK, les résultats
CI distants et la recette sur appareil réel. Le code et les résultats cloud sont prêts
à examiner ; la fusion/publication doivent attendre ces vérifications.
